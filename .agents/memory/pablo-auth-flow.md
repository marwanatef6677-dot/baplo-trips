description: The selected authentication method and required Egyptian phone number for Pablo users.

Keep Replit-managed Clerk email/password sign-in. Every user must provide a valid Egyptian mobile number in their profile before accessing ride features; the phone number is profile contact data, not the login identifier.

Customers must self-attest that they are at least 18, accept the current customer terms, and type the same full name as their profile before booking. Store the signed name, acceptance time, age attestation, and terms version; this does not verify identity or age. The current terms are a draft and need review by an Egyptian lawyer before commercial launch.

**Why:** The user chose to keep email and password while requiring an Egyptian phone number for each account, and explicitly requested adult-customer consent to the user terms.

**How to apply:** Do not switch Pablo to phone-based login or add SMS sign-in without a new decision and an external authentication provider. Require customers to accept again when the terms version changes; never present the typed-name record as a guarantee of legal validity.
